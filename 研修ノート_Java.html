Java

  • いままでの言語（C言語）などは、OS依存だった（Mac用に作ったら、Windowsで動かない）
  • JavaはJVM（Java仮想マシン）によって、非依存性の言語が売りだった
  • Javaはガベージコレクションでメモリ管理をしなくていい
    • C言語はメモリ管理が必須だった

テスト

  • プログラミング言語を機械語に翻訳することをコンパイルするといい、翻訳ソフトをコンパイラという
    • Javaは2度に分けて翻訳する
    • コンパイル後はバイトコードと呼ばれる中間言語に変換され、クラスファイルが作成される
    • 実行時にインタプリタがバイトコードを機械語に翻訳して実行してくれる
    • クラスファイルをOSごとのJVMが読み取りOSごとの機械語に翻訳するため、OSに依存しない
  • 翻訳方法の違い
    • コンパイラ：ソースコード全体を一気に翻訳する
    • インタプリタ：実行ごとに、クラスファイルを一行ずつ翻訳する

アクセス修飾子

原則、フィールドにはprivate、メソッドにはpublicをつける。

アクセス修飾子 説明
private修飾子 他のクラスからアクセスできない
public修飾子 他のクラスからアクセス可能

private と public を利用すれば想定外の値の受け渡しを防ぐことができる。

アクセス修飾子
修飾子名 アクセスを許可する範囲 記述できる場所
private 同一クラスのみ フィールド、メソッド、コンストラクタ
記述なし 同一パッケージのみ フィールド、メソッド、コンストラクタ、クラス
protected 同一パッケージ内のクラス、または自身を継承したクラス（パッケージが異なる場合でもアクセス可能） フィールド、メソッド、コンストラクタ
public すべてのクラス フィールド、メソッド、コンストラクタ、クラス

カプセル化

private メンバへの操作について、public メンバを経由するようにアクセス制限をかけることをカプセル化という。

  • フィールドに値を代入するためのメソッドをsetter（setterメソッド）という。

クラス型の変数

値渡しと参照渡しとは、変数への代入やメソッドの引数、戻り値のデータの受け渡し方を表す言葉。

用語 仕組み 内容 対象の型
値渡し 基本型による値の代入 値をコピー int、double
参照渡し 参照型による値の代入 参照情報（メモリ上の住所）をコピー String、オブジェクト

値渡しは、渡した先の変数を変更しても、元の変数に影響はない

参照渡しは、代入先で値を編集すると、代入元の値も変わる

イミュータブル：「不変」「変更不可能」を意味すし、作成後に状態や値を変更できないデータやオブジェクトを指す

null

  • 基本型には入らない。

Javaは、オブジェクトがどの変数からも扱われなくなった場合、ガベージコレクションにより、オブジェクトが破壊される

// 明示的に、スーパークラスの引数なしコンストラクタを呼び出す
public サブクラス {
    super();
    処理;
}

// スーパークラスの引数ありコンストラクタを呼び出す
public サブクラス {
    super(引数リスト);
    処理;
}

this() そのクラスの別のコンストラクタを呼び出す
super() そのクラスのスーパークラスのコンストラクタを呼び出す

protected修飾子

スーパークラスのprivateメンバには、サブクラスからもアクセスできない。

サブクラスからスーパークラスのメンバにアクセスしたい場合は、protected修飾子を指定する。

// スーパークラス
public class スーパークラス名 {
    protected data;
}

// サブクラス
public class サブクラス名 {
    a = data; // 変数名だけでアクセスできる
}
修飾子一覧
修飾子名 アクセスを許可する範囲 記述できる場所
private 同一クラスのみ フィールド、メソッド、コンストラクタ
記述なし 同一パッケージのみ フィールド、メソッド、コンストラクタ、クラス
protected 同一パッケージ内のクラス、または自身を継承したクラス（パッケージが異なる場合でもアクセス可能） フィールド、メソッド、コンストラクタ
public すべてのクラス フィールド、メソッド、コンストラクタ、クラス

注意

スーパークラスと同じ名前の変数をサブクラスで宣言してはいけない
変数隠しといい、コンパイルエラーはでないが正しく動作しない

オーバーライド

スーパークラスで定義されたメソッドと同じ名前（シグネチャ）のメソッドをサブクラスで再定義することです。

シグネチャとは、メソッド名・引数の型・個数・順番の組み合わせを指す言葉。

つまり、サブクラス内では、スーパークラスで定義されたメソッドと同じメソッド名、引数の型、個数、順番であるメソッドを定義できる。

オーバーライドが出来ない場合

  1. メソッドにfinalを指定している場合
  2. staticメソッド

アノテーション

@Override // 親クラスのメソッドを上書きしていることをコンパイラに宣言し、記述ミスを防ぐための目印。

様々な機能を付け加えることができる。
コンパイラやフレームワークに対し、コードの役割や指示といった「補足情報」を伝えるためのタグ。

継承のメリット

継承をするとスーパークラスのグループとして扱える。

親クラスの変数に子クラスを代入することができる。

// スーパークラス
public class Phone {
    public void show() {
        System.out.println("これは携帯電話です。");
    }
}

// サブクラス
public class SmartPhone {
    @Override
    public void show() {
        System.out.println("これはスマートフォンです。");
    }
}

// 実行クラス
public class Main {
    public static void main(String[] args) {
        Phone p = new Phone();
        SmartPhone sp = new SmartPhone();

        Phone[] phones = {p,sp}; // スーパークラスの配列にサブクラスをいれることができる

        for (Phone phone : phones) { // スーパークラスにサブクラスを代入することができる
            phone.show(); // 同じメソッド名だが、代入したオブジェクトによって動作が変わる
        }
    }
}

抽象クラスと抽象メソッド

  • 不要なクラスを生成させたくない
  • オーバーライドを強制させたい

上記2点を解決するために、抽象クラスと抽象メソッドがある。

abstractという修飾子をつける

public abstract class クラス名 {
    abstract void メソッド名(); // 抽象メソッドは{}を記述できない

    // 具象メソッドも書くことができる
    public void メソッド名() {
        処理;
    }
}

抽象クラスはオブジェクト生成ができない。
※ 具体的な処理が書かれていないため

抽象クラスを継承したクラスの中で、抽象メソッドの内容をそれぞれ記述し、オブジェクト生成をする。
そのため、オーバーライドを必ず行う必要がある。

abstractの特徴
1 abstractのついたクラスは newすることはできない
2 abstractがついたクラスは abstractのついたメソッドを最低一つは持つ
3 abstractがついたクラスは extendsして使われる
4 abstractがついたクラスは通常のフィールドやメソッドも定義できる
5 abstractがついたメソッドはオーバーライドされることを強制できる
6 オーバーライドが完了した子クラスはnewできる

カプセル化

カプセル化とは、フィールドとメソッドを1つのクラスにまとめ、保護したいメンバにprivateを付けることで外からのアクセスを制限する仕組みのこと。

保守性の向上やバグに強いプログラムの作成に繋がる。

public すべてのクラス フィールド、メソッド、コンストラクタ、クラス

継承

継承とは「あるクラスのメンバを他のクラスに引き継がせる」仕組みのこと。

継承を用いることで、プログラムの再利用性を高め、保守・修正を容易にすることができる。

ポリモーフィズム（多態性）

ポリモーフィズムとは、同じ名前のメソッドでも、オブジェクトに応じて異なる振る舞いを持たせることのできる仕組みのこと。

ポリモーフィズムを実現する仕組みとして、オーバーライドがある。

パッケージ

パッケージとは、クラスをまとめて分類するための仕組みで、クラスを機能や役割別に分類することでクラスを管理しやすくする。

すべてのクラスは必ずパッケージに属さなければいけない。パッケージを指定しない場合は、デフォルトパッケージというパッケージに暗黙的に属することになる。

パッケージが異なれば、1つのシステム内に同名のクラスを複数作成することができる。

パッケージのようにクラス名などの識別子を重複させないための仕組みを「名前空間」と呼ぶ。

異なるパッケージ内のクラスへのアクセス

  1. アクセスされるクラスのアクセス修飾子をpublicにする
  2. パッケージ名を含めたクラス名（完全修飾子）を指定する

インポート

異なるパッケージ内のクラスにアクセスするたびに、完全修飾名を記述するのは不便です。

そこで、import文を記述することで、クラス名だけでアクセスできるようになる。

import パッケージ名.クラス名;

整列アルゴリズムは、データを昇順、降順に並び替えるアルゴリズムのこと。

  4. これを配列の要素数回繰り返す
